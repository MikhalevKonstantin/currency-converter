# Analytics Setup

The website is wired for analytics but **no provider is switched on yet**, so nothing is collected. Pick one, paste an ID into `config.json`, rebuild and deploy.

Analytics is **web only**. The Android and iOS apps never load it, which keeps their privacy declarations simple.

## Choose a provider

| Provider | Cost | Cookies | Custom events | Notes |
|---|---|---|---|---|
| **Umami Cloud** (recommended to start) | Free tier (limited events/month) | None | Yes | Simple dashboard, good for this app |
| Plausible | Paid after trial (about $9/month) | None | Yes (use the `tagged-events` script, already set) | Very polished; EU-hosted |
| GoatCounter | Free for non-commercial use only | None | Basic | This site has affiliate links and ads, so check their terms before using |
| Google Analytics 4 | Free | Yes | Yes | Loads only after a visitor clicks Accept on the cookie banner |

## Switch it on (Umami example)

1. Create an account at umami.is, add a website, and set its domain to `mikhalevkonstantin.github.io` (or your own domain later).
2. Copy the **Website ID**.
3. In `config.json`:
   ```json
   "analytics": {
     "provider": "umami",
     "umamiWebsiteId": "PASTE-ID-HERE"
   }
   ```
   (Keep the other fields as they are.)
4. Rebuild and deploy:
   ```bash
   SITE_URL=https://mikhalevkonstantin.github.io/currency-converter node build.js
   ```
   then push `dist/` to the `gh-pages` branch as before.

Other providers: set `provider` to `plausible` (+ `plausibleDomain`), `goatcounter` (+ `goatcounterCode`) or `ga4` (+ `ga4Id`).

## What is recorded

Page views happen automatically. Every page for a currency pair has its own address, so top pairs show up as top pages.

| Event | Properties | Answers |
|---|---|---|
| `convert` | `pair` (e.g. `USD-MXN`) | Which pairs people really use (after 1.5 s on a pair) |
| `affiliate_click` | `pair`, `offer` (`route` or `generic`) | Do route-specific offers get more clicks than the generic one? |
| `fav_add` | `currency` | Which currencies people care about |
| `share`, `copy_link` | `where` | Do people share? |
| `use_case` | `use` (travel / shopping / sending-money / work / other) | Which audience segment you really have |

**Never recorded:** the amounts typed, anything personal, or anything from the apps. Visitors who send Do Not Track are not tracked at all.

## The one-question survey

After a visitor has tried 3 different pairs, a small "What do you mostly use this for?" card appears once. It only appears when analytics is on. The answer goes out as the `use_case` event. This is how you test the audience guesses in `AUDIENCE.md`.

## What to look at after 2 to 4 weeks

1. **Top pages:** which pairs bring visitors. Add more currencies for the winning corridors.
2. **`affiliate_click` by `offer`:** if `route` beats `generic`, write more specific copy per corridor in `offers.json`.
3. **`use_case` split:** if "sending money" is large, build rate alerts; if "travel" dominates, build the offline and widget features first.
4. **Countries and devices** (in the provider dashboard): decide which languages to translate first.

## Privacy policy

`privacy.html` is generated by `build.js` and already describes analytics (cookieless, or GA4 with consent), ads, purchases and affiliate links. It reads `contactEmail` from `config.json`. Add that field with your real contact address before applying to AdSense or the stores; until then it shows a placeholder.
